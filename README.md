# hwp2docx · docx2hwpx

한글 문서(`.hwp`)와 Word 문서(`.docx`)를 서로 바꿉니다. 한컴오피스도, 인터넷 연결도 필요 없습니다.

| 방향 | 끌어다 놓을 곳 | 결과 |
|---|---|---|
| 한글 → Word | `2_한글파일을_여기에_끌어다놓기.bat` | `.docx` |
| Word → 한글 | `3_워드파일을_여기에_끌어다놓기.bat` | `.hwpx` (한글 2014 이상에서 더블클릭으로 열림) |

## 윈도우에서 — 끌어다 놓기

터미널을 쓰지 않아도 됩니다.

1. 이 폴더의 **`1_처음에_한번_설치.bat`** 를 더블클릭합니다. 처음 한 번만 하면 됩니다.
2. 그다음부터는 한글 파일을 **`2_한글파일을_여기에_끌어다놓기.bat`** 아이콘 위로
   끌어다 놓기만 하면 됩니다. 같은 폴더에 Word 파일이 생깁니다.

파일 여러 개를 한꺼번에 끌어다 놓아도 되고, 폴더를 통째로 끌어다 놓아도 됩니다.
자주 쓰신다면 `2_...bat` 의 바로 가기를 만들어 바탕화면에 두세요.

끌어다 놓기는 한컴 전용 글꼴을 어디서나 열리는 글꼴로 바꿔서 변환합니다(`--safe-fonts`).
원본 글꼴 그대로가 좋다면 `2_...bat` 을 메모장으로 열어 `--safe-fonts` 를 지우면 됩니다.

## Word → 한글 (docx2hwpx)

결과는 `.hwpx`입니다. 한글의 공식 표준 형식이라 한글에서 그대로 열리고, 꼭 `.hwp`가
필요하면 한글에서 "다른 이름으로 저장"하면 됩니다.

```bash
python -m docx2hwpx.cli 문서.docx
python -m docx2hwpx.cli 폴더 -r -o 변환본
```

한글 2024가 직접 저장한 빈 문서를 뼈대로 쓰고(python-hwpx 프로젝트, Apache-2.0,
`docx2hwpx/data/NOTICE`), 그 뼈대에 서식과 본문을 덧붙입니다.

**줄 간격.** Word의 "줄 간격 2배"는 글꼴마다 실제 높이가 다르고, 한글의 "200%"는
글자 크기 기준입니다. 그래서 윈도우에 설치된 **실제 글꼴 파일**을 읽어(Word가 쓰는 것과
같은 winAscent+winDescent 값) 환산합니다. 글꼴 파일을 못 찾으면 표의 근삿값(기본 1.2)을
쓰므로, 되도록 그 글꼴이 설치된 PC에서 변환하세요.

**옮기는 것.** 글꼴·크기·굵게·기울임·밑줄·취소선·색·형광펜·위/아래 첨자·자간·장평,
정렬·여백·들여쓰기/내어쓰기·문단 간격·줄 간격·쪽 나눔, Word 스타일 상속(문서 기본값 →
표 스타일 → 문단 스타일 → 번호 → 글자 스타일 → 직접 서식), 자동 번호·글머리표(글자로 풀어서),
표(가로·세로 병합, 셀별 테두리·배경, 셀 여백, 머리글 행 반복), 그림, 용지·여백·여러 구역.

**못 옮기는 것.** 머리말·꼬리말, 각주·미주, 차트, 도형·SmartArt, 수식(글자로만), 글상자(본문으로
풀어서), 변경 내용 추적(삭제된 글자는 빼고 삽입된 글자는 넣음), 메모.

**확인되지 않은 것.** 가로 용지를 한글에 어떻게 적는지(`NARROWLY`)는 실제 한글 파일로 확인하지
못했습니다. 가로 문서는 변환 후 용지 방향을 확인해 주세요.

`tests/compare_docx_hwpx.py`로 원본과 결과를 문단 단위로 대조할 수 있습니다(글자, 글꼴, 크기,
굵기, 정렬, 문단 간격, 줄 간격 종류, 용지·여백).

## 한글 → Word (hwp2docx)

### 명령줄에서

```bash
pip install olefile python-docx

# 한 파일 — 원본 옆에 문서.docx 를 만듭니다
python -m hwp2docx.cli 문서.hwp

# 폴더 통째로 (-r 은 하위 폴더까지)
python -m hwp2docx.cli ~/내문서/양식 -r -o ~/내문서/변환본

# 한컴 전용 글꼴을 어디서나 열리는 글꼴로 바꿔서
python -m hwp2docx.cli 문서.hwp --safe-fonts

# 글꼴을 직접 지정
python -m hwp2docx.cli 문서.hwp --font "함초롬바탕=바탕" --font "함초롬돋움=맑은 고딕"

# 변환이 제대로 됐는지 원본과 대조
python -m hwp2docx.cli 문서.hwp --check
```

`pip install -e .` 로 설치하면 `hwp2docx` 명령으로 바로 쓸 수 있습니다.

파이썬에서 직접 부를 수도 있습니다.

```python
from hwp2docx import convert

result = convert("문서.hwp", "문서.docx", safe_fonts=True)
print(result.ok, result.warnings)
```

## 세로 위치가 맞는 이유

한글과 Word는 줄 간격과 문단 간격을 쌓는 규칙이 서로 다릅니다. 한글은 줄 간격
120%를 글자 크기의 120%로 계산하지만 Word는 글꼴이 가진 줄 높이의 120%로 계산하고,
문단 위·아래 간격을 합치는 방식도 다릅니다. 그래서 문단 모양 값을 그대로 옮기면
문서가 조금씩 아래로 밀려 내려가고, 긴 문서에서는 쪽 수까지 달라집니다.

이 도구는 그 규칙을 추측하지 않습니다. `.hwp` 안에는 한글이 저장할 때 계산해 둔
**실제 줄 배치 결과**(`PARA_LINE_SEG`: 줄마다의 세로 위치, 높이, 줄 간격)가 들어
있습니다. 표 역시 개체가 정확한 폭과 높이를 갖고 있습니다. 이 좌표에서 문단 사이
간격을 역산해 Word의 고정 줄 높이로 옮깁니다.

덕분에 실제 양식 문서에서 첫 쪽 요소들의 세로 위치 오차가 **최대 0.9mm, 평균
0.4mm**, 가로 오차가 0.4mm 수준입니다. `--no-layout` 을 주면 이 방식을 끄고 문단
모양 값만 씁니다.

## `--check` 가 하는 일

`.hwp` 안에는 한글이 그려 둔 첫 쪽 미리보기 그림이 들어 있습니다. `--check` 는
변환 결과를 PDF로 렌더링한 뒤 두 그림에서 글자와 선이 있는 가로 띠를 찾아 세로
위치를 비교하고, 오차를 밀리미터로 알려 줍니다. 눈으로 열어 보지 않고도 밀리거나
눌린 문서를 찾을 수 있습니다.

LibreOffice(`soffice`), `pdftoppm`, Pillow, numpy 가 있어야 동작하고 없으면 조용히
건너뜁니다.

## 옮기는 것

용지 크기와 방향, 네 방향 여백, 머리말·꼬리말 자리 · 문단 정렬, 들여쓰기와 내어쓰기,
왼쪽·오른쪽 여백, 문단 간격, 줄 간격 · 글꼴(한글·영문 따로), 크기, 굵게, 기울임,
밑줄, 취소선, 위·아래 첨자, 글자 색, 음영, 자간, 장평 · 표의 행·열, 가로 병합과 세로
병합, 셀별 폭과 높이, 셀별 테두리 종류·두께·색, 셀 배경색, 셀 안쪽 여백, 세로 정렬,
표 안의 표 · 그림(문서에 박힌 것) · 탭과 강제 줄 나눔, 묶음 빈칸 · 여러 구역(구역마다
다른 용지 설정) · 한컴 기호 글꼴의 원문자(①~⑳) 등을 표준 문자로 변환

## 옮기지 못하는 것

변환하면서 만나면 경고로 알려 줍니다.

- **수식** — 한글 수식 편집기와 Word 수식은 표현이 달라 1:1 대응이 없습니다. 자리가 빕니다.
- **각주·미주, 머리말·꼬리말 내용** — 자리만 비우고 내용은 옮기지 않습니다.
- **글상자** — 본문 문단으로 풀어서 옮깁니다. 위치가 달라집니다.
- **차트, 그리기 개체(선·도형), OLE 개체**
- **누름틀(입력 양식), 메모, 변경 내용 추적**
- **배포용 문서, 암호 문서, DRM 문서** — 본문이 암호화되어 열 수 없습니다. 한글에서 해제 후 다시 저장해 주세요.
- **HWP 3.x 이하, `.hwpx`** — 형식이 완전히 다릅니다. `.hwpx`는 XML 기반이라 나중에 별도로 붙일 수 있습니다.

## 글꼴에 대해

기본값은 원본 글꼴 이름을 그대로 씁니다. 함초롬바탕·함초롬돋움은 한컴오피스와 함께
설치되는 글꼴이라, 한컴오피스가 없는 PC에서 문서를 열면 다른 글꼴로 대체되고 그
순간 줄바꿈 위치가 바뀝니다. 문서를 남에게 보낼 거라면 `--safe-fonts` 를 쓰는 편이
안전합니다.

## 한계

표와 문단 중심의 양식·보고서 문서를 겨냥해 만들었습니다. 그 범위에서는 원본과
거의 같은 결과가 나오지만, 두 가지는 원리적으로 맞출 수 없습니다.

하나는 글꼴입니다. 글꼴이 대체되면 글자 폭이 달라지고, 글자 폭이 달라지면 줄바꿈
위치가 바뀌며, 줄이 하나 늘면 그 아래가 전부 밀립니다. 여러 줄로 감기는 긴 문단이
많은 문서일수록 오차가 커집니다.

다른 하나는 위에 적은 미지원 요소들입니다. 수식이나 그리기 개체가 많은 문서라면
이 도구보다 한글의 "다른 이름으로 저장 → Word 문서" 기능이 나을 수 있습니다.

## 구조

| 파일 | 하는 일 |
|---|---|
| `reader.py` | OLE 복합 파일 열기, 스트림 압축 해제, 레코드 순회와 트리 구성 |
| `tags.py` | 레코드 태그와 제어 문자 상수 |
| `docinfo.py` | 문서가 공유하는 서식표(글꼴·글자 모양·문단 모양·테두리) |
| `bodytext.py` | 본문을 문단·표·그림 모델로 |
| `model.py` | 한글과 Word 사이의 중간 문서 모델 |
| `writer.py` | 모델을 OOXML로 |
| `verify.py` | 원본 미리보기와 대조 |
| `text.py` | 한컴 기호 글꼴 문자 변환 |
| `cli.py` | 명령줄 |

시험은 `python3 tests/test_writer.py` 로 돌립니다. 병합 셀, 중첩 표, 그림, 여러
구역, 배치 정보가 없는 문서 등 실제 파일 하나로는 지나가지 않는 경로를 확인합니다.
